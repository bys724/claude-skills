# Code Cleaner - 최소주의 리팩토링 가이드

사용자가 코드 정리나 리팩토링을 요청하면 아래 원칙에 따라 작업하세요.

## 핵심 철학: "Less is More"

### 1. 제거 우선 순위
- **즉시 삭제**:
  - 임시방편(workaround) 코드
  - 사용하지 않는 기능 (예: uninstall 스크립트)
  - "나중을 위한" 코드 (YAGNI 위반)
  - 중복 코드/파일

### 2. 파일 관리 원칙
- **새 파일 생성 최소화**:
  - 기존 파일에 기능 추가 우선
  - 필요시 주석 처리 허용
  - 목적이 비슷하면 통합

- **백업 처리**:
  - 중요 변경 시: `.backup.날짜` 생성
  - 작업 완료 후: 백업 즉시 삭제
  - 영구 백업 금지

### 3. 문서화 전략
- **코드 주석**:
  - 자세한 설명은 코드에만
  - WHY > WHAT

- **문서 구분**:
  - 한글: 사용자용, 간략하게 핵심만
  - 영어: Claude용, 기술 상세 (README 등)

- **레거시 기록**:
  - 코드 보관 ❌
  - 간략한 문서 기록 ✅ (Archive/*.md)

### 4. 디렉토리 구조
```
project/
├── core/          # 핵심 기능만
├── scripts/       # 반복 사용 스크립트만
├── Archive/       # 과거 기록 (문서만)
└── README.md      # 일회성 명령어 문서화
```

### 5. 리팩토링 체크리스트
```bash
# 1. 사용 빈도 확인
git log --oneline file.sh  # 실제 사용 이력

# 2. 중복 제거
grep -r "similar_function"  # 유사 기능 찾기

# 3. 통합 가능성 검토
# 비슷한 목적 = 하나의 파일로

# 4. 정리 후 확인
tree -L 2  # 구조 명확성 체크
```

## 실행 예시

### Bad ❌
```bash
scripts/
├── install.sh
├── install-dev.sh       # 중복
├── install-prod.sh      # 중복
├── uninstall.sh        # 사용 안 함
└── backup-20240301.sh  # 레거시
```

### Good ✅
```bash
scripts/
├── setup.sh  # 통합 (--dev/--prod 옵션)
└── README.md # uninstall 명령어 문서화
```

## 작업 순서
1. **분석**: 실제 사용 패턴 파악
2. **제거**: YAGNI 위반 코드 삭제
3. **통합**: 중복/유사 기능 합치기
4. **문서화**: 삭제한 기능 중 필요한 것만 README에
5. **검증**: 구조 명확성 확인

## 금지 사항
- ❌ "혹시 모르니" 남겨두기
- ❌ 백업 파일 영구 보관
- ❌ 비슷한 기능 별도 파일로
- ❌ 과도한 자동화
- ❌ 레거시 코드 보관
